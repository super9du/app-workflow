# 按设计开发（develop）

Web、PC 客户端、手机客户端、微信小程序等大前端界面开发，只要有相关设计资料，就自动执行本流程。无需用户输入 develop；不意味着每次都重新 init。

## 编码前分析

读取本次相关设计、规范、token 和代码。明确用户是要求还原还是仅参考风格，检查页面、交互及本次需要的状态。

检索现有组件与项目已采用的组件库，检查接口、交互、状态、主题、尺寸与平台兼容性，不能只看名字和外观。

给用户简短组件方案，说明直接复用、兼容扩展、新增以及保留局部结构的部分及原因；可用小表格，不要求逐项批准。存在影响结果的设计冲突时先确认关键决策。

## 拆分与实现

按职责、变化方式和真实复用场景从小到大拆分，再按依赖顺序实现。卡片含标题、内容、步进器时，不能只做大卡片而忽略内部可复用单元：独立交互的步进器优先复用或提取；有统一结构的标题可提取；普通说明文字通过 token 或共享样式复用。只在当前卡片使用且无独立职责的结构可局部实现，避免空壳组件和猜测性抽象。

先基础组件，再业务组合组件，最后页面。业务状态、持久化、页面布局和手势按现有边界保留，不因抽组件改变行为。扩展公共组件保持现有调用兼容。

颜色、字体、间距、圆角等使用既有 token；业务值和动态计算不强制 token 化。新稿与现有规范冲突时，指出具体差异，确认局部例外还是全局调整，不擅改全局 token 或悄悄偏离设计。

缺少设计基础时说明缺项，引导用户补齐或进入 init；个别 token 缺口提出局部补充方案，不重建整套设计体系。

## 辅助能力与验证

根据任务选用平台开发、Figma、诊断、设计等技能。需要导图用 [HTML 转图片](html-to-image.md)；需要图标位图用 [SVG 转 PNG](svg-to-png.md)。不为了流程完整而调用无关工具。

检查受影响的交互与状态；视觉实现对照设计检查实际渲染，包括任务相关的主题、长内容和视口。HTML 原型不代替客户端或小程序真实平台验证。按项目约定和任务授权选择验证工具。

按需更新已有组件目录；不为每次开发重写 DESIGN.md 和 token。交付说明完成内容、验证结果及未验证部分。用户只要原型时，不顺带修改生产实现。
