# 项目设计配置（init）

目标：确定可供后续开发使用的 DESIGN.md 和 design token。初始化不意味着重新创建项目、替换技术栈或重做已有设计。

## 检查 Git 环境

开始 init 时，先对当前项目运行随技能提供的脚本：

```bash
node <skill-dir>/scripts/setup-git.cjs <项目目录>
```

脚本检查 Git 是否可用；项目尚未属于 Git 仓库时执行 `git init`，已有仓库（包括父级仓库和 worktree）则复用，不重复创建。只初始化仓库，不自动暂存、提交或修改 Git 身份和远程配置。

- 退出码 `0`：已有或已初始化本地仓库，可以继续。
- 退出码 `2`：未安装 Git，提示用户安装，安装后重新运行；不自动安装，不将仓库初始化报告为成功。
- 其他非零退出码：说明路径、权限或 Git 环境等错误，排查后继续，不反复初始化已有仓库。

说明可选关联 GitHub 或 Gitee：远程仓库便于异地备份、跨设备同步和团队协作。本地版本记录与回退不依赖托管平台；用户不愿关联时，直接采用本地 Git 开发。已有远程配置继续沿用，仅在用户选择并授权后处理登录、远程关联或推送。

## 检查已有基础

先检查代码、主题配置、token、组件、DESIGN.md 或同类规范，以及原型、HTML、截图和 Figma。沿用现有有效内容与路径，重复 init 只补缺项。

| 已有资料 | 处理方式 |
| --- | --- |
| 已有规范与 token | 核实适用性，补缺项，不重新选择风格 |
| 代码与设计资料 | 提取共同规则；列出当前实现与目标设计的关键冲突 |
| 只有代码 | 从主题、样式和组件提取，必要时看实际渲染 |
| 只有设计图或截图 | 提取可观察规则；无法确定且影响实现的事项在回答中说明 |
| 均无可用资料 | 按下节明确产品并探索方向 |

不在 DESIGN.md 或 token 中添加来源、置信度、推断等额外标记；不从单张截图虚构全部交互和状态。

## 从零确定方向

简短了解应用类型（Web、PC 客户端、手机客户端、微信小程序或多平台）、目标系统、目标用户、核心任务、首批页面及风格偏好。询问有无草图、截图、原型或参考产品；用户不懂风格术语时提供具体示例。

按 [设计方案选择](design-options.md) 推荐路径；必要时先做同一核心页面的 2～3 个方案。根据用户需求和偏好，优先通过已安装搜索 skill 或现成搜索 API 自动检索 DESIGN.md 案例；结果不足时补充直接检索。

可从 [Google Labs DESIGN.md 示例](https://github.com/google-labs-code/design.md/tree/main/examples) 和相关公开项目查找。提供少量候选，说明适合之处、需要调整的部分、来源链接及可用预览。必要时制作示意预览并在回答中说明。找不到匹配案例就如实说明，不把自生成方案冒充网上案例。用户选定方向后再形成正式规范。

## 建立规范与 token

参考 [Google Labs DESIGN.md 规范](https://github.com/google-labs-code/design.md)，使用执行时有效的规范，不把某个旧版 skill 模板视为最新标准。新建文档优先采用兼容结构；已有文档按需增量完善，较大重构遵循入口约定。

DESIGN.md 说明视觉方向、颜色角色、字体、布局、层次、形状、组件规则与必要的使用约束。确定设计 token，并提供适合当前技术栈的可复用定义，让组件代码引用。设计属性遵循 token；业务数值和动态计算无需 token 化。不要为文档组织额外添加来源说明或重复维护的说明文件。

按输入选择辅助技能：
- 代码提取：可推荐 [Google Labs extract-design-md](https://github.com/google-labs-code/stitch-skills/blob/main/plugins/stitch-design/skills/extract-design-md/SKILL.md)，先核实当前要求。
- 截图控件提取：可用 screenshot-to-design-system，但其不负责整页布局、背景和图标，不能独自充当完整规范。
- token 与组件规范：可用 design-system。
- 只有用户已有 Stitch 设计或明确选择 Stitch，才进入 Stitch 相关技能流程。

## 平台技能与完成条件

识别平台后检查官方技能。微信小程序开发必须检查 miniprogram-development，缺少时提醒安装并提供 [腾讯云官方来源](https://github.com/TencentCloudBase/skills)。其他平台（包括小红书小工具）也应通过技能发现或搜索能力检查是否有官方技能，核实来源与适用性；没有就如实说明，不编造官方身份。

完成时简要交付规范位置、token 使用方式、已有组件入口及必要的安装提醒。组件目录优先更新已有文件，确有查找需要时再新增。
