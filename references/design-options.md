# 设计方案选择

用户需要制作设计稿或 init 缺少设计依据时读取。先了解要选视觉风格、验证操作流程，还是交付可编辑设计资产；用户已指定媒介就遵循，不重复选择。

| 路径 | 适用场景 | 推荐方式 |
| --- | --- | --- |
| 概念图 → 按图开发 | 视觉探索、展示页、初版 Demo | 用 imagegen 生成同一核心页面的少量不同方向，选定后开发；交互复杂时补关键流程原型 |
| HTML 交互原型 → 正式开发 | 表单、工具、后台、功能型页面 | 默认优先考虑；可预览、操作并读取源码，选定后按项目组件与平台规范整理实现 |
| Figma → 开发 | 已有设计资产、团队批注、精细画布编辑、组件库维护 | 提示需要使用 Figma，按下节选择连接方式 |

这是按任务选择的建议，不是固定流水线。图片能表达外观，不能独自表达响应式、交互和全部状态；HTML 也不替代原生平台验证。手机客户端区分 iOS/Android，PC 考虑窗口与键鼠，小程序遵循平台导航及原生组件约束。

## 控制探索范围

先做同一核心页面的 2～3 个明显不同方案，保持功能与主要文案一致；用户选择后只展开选中方向，不为所有候选生成整套页面和完整 token。方向已明确可直接进入原型或开发，不强制先生成图片。

init 的探索稿可用临时样式，方向选定后确定正式 DESIGN.md 与 token。develop 使用现有规范，不重复走风格选择。

本地可用能力按需选择：ui-ux-pro-max 用于风格与布局方向；prototype 用于多方案交互探索；impeccable 或 design-taste-frontend 用于设计与打磨，选择一个主要技能；imagegen 用于位图概念图。探索代码不是生产代码，正式实现需检查组件边界。缺少能力时可通过 find-skills 或搜索 API 查找可信技能，如 [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，不默认重复安装已有同类能力。

## Figma 路径

用户已有官方 MCP 所需权益且连接可用时，可优先官方 MCP；不要仅凭“有会员”就断定具备权限或额度，执行时核实。没有对应权益或希望使用替代方案时，推荐 figma-content-operator，并提示需要 Figma 与相应插件连接；用户指定工具就遵循。

使用 figma-content-operator 前读取其 SKILL.md：已有画布局部修改走画布；完整页面、响应式和多状态可先做网页再按需转入 Figma。不要默默替换用户指定的交付媒介，也不要擅自上传到外部服务。

## 如何给用户建议

简短说明推荐路径、理由、交付形式及必要环境即可。不宣称 Figma 一定比图片消耗某个比例的 token；成本取决于读取范围、节点规模、修改次数、图片生成与返工。重点减少重复制作和无关上下文。

可借鉴的官方实践：
- [v0 截图转界面](https://v0.app/docs/screenshots)：图片配合交互说明作为实现输入。
- [v0 Design Mode](https://v0.app/docs/design-mode)：在可运行预览中调整并应用回代码。
- [Figma Code to canvas](https://help.figma.com/hc/en-us/articles/40219873508247-Workflow-lab-Code-to-canvas)：需要时将代码原型转为可编辑画布。

上述是流程依据，不要求使用这些产品。用户需要设计建议时按需提示，不在每次开发中重复介绍。
